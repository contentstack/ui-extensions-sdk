# ui-extensions-sdk

`@contentstack/ui-extensions-sdk`: the legacy (pre-Marketplace) UI extensions SDK. Existing custom fields, custom widgets and dashboard widgets in customers' stacks load it from npm/unpkg (`dist/ui-extension-sdk.js`, UMD global `ContentstackUIExtension`). It does the `init` handshake with the Contentstack host (UI-React) over post-robot and exposes `extension.field`, `entry`, `window`, `stack` and `store`. New work belongs in `@contentstack/app-sdk`; this repo gets bug and security fixes.

## Public API contract (hard rules)
- This package is public and runs inside customers' existing extensions. No breaking change: the `ContentstackUIExtension` global, exported classes, method names and signatures, the `init`/`ready` handshake, post-robot channel names (`init`, `ready`, `extensionEvent`, `stack`, ...) and payload shapes stay as they are.
- Change runtime behaviour only for a confirmed bug fix, and say in the PR exactly what consumers will see differ. Every other PR says it changes nothing for consumers.
- Host-to-extension listeners (`postRobot.on`) must accept messages from `window.parent` only (`{ window: window.parent }`); see MKT-22139.
- No `console.log` of entry, field or user data; never log tokens, headers or bodies.
- Error messages are part of the contract (extensions may match them): keep the current text as the prefix.
- A version bump, release or `npm publish` is the release process's job (GitHub release -> `.github/workflows/npm-publish.yml`, which runs `npm test` first), never part of a feature or fix PR.

## Layout
| Path | Purpose |
|------|---------|
| `lib/index.js` | `ContentstackUIExtension.init()` entry, `SDK_VERSION` |
| `lib/extension.js` | `init` handshake, location objects, host event routing (`extensionEvent`) |
| `lib/field.js`, `entry.js`, `window.js`, `store.js` | field, entry, iframe size and store APIs |
| `lib/stack/` | `stack` queries (content types, entries, assets) |
| `test/*Spec.js` | Karma/Jasmine specs; `test/data/` fixtures |
| `docs/ui-extensions-api-reference.md` | API reference (public) |
| `jsdocs/` | generated by the build; `.github/readme/blueprint.md` generates `README.md` |

## Review rules (from the `master` ruleset)
The ruleset "Default branch protection rules for releases branch" covers `master`:
- Changes land by pull request only; no force push, no branch deletion.
- 1 approving review, including a code owner (`CODEOWNERS`: `@contentstack/developer-ecosystem-pr-reviewers`; workflows, `.snyk`, `CODEOWNERS` and `.gitguardian.yaml` need `@contentstack/security-admin`).
- The last push needs approval from someone other than its pusher; new pushes dismiss stale approvals; all review threads must be resolved.
- Required checks: `GitGuardian Security Checks`, `security-sca`, `security-license`, `security-policy`, `security/snyk`, `code/snyk`, `license/snyk` (contentstack-developer-ecosystem). Tests are not a required check: run `npm test` yourself. Until #69 merges no workflow runs them on pull requests; after it, read the `Unit tests` run on the PR.
- Merge, squash or rebase are all allowed. Release tags are protected by a separate ruleset.

## Definition of Done
- `npm test` is green, with a spec for every public method the change adds or changes, written from the docs, not from the code's output.
- `npm run build` passes and adds no new ESLint warning.
- The PR states the consumer impact (none, or exactly what changes).
- `docs/ui-extensions-api-reference.md` updated for public API changes; README regenerated from the blueprint when the usage changes.
- No secrets in code, commits or logs.
